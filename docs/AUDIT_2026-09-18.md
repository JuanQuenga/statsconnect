# Codebase audit and UI polish

## Scope

This pass reviewed the three app entry points, home screens, player search, shared navigation, profile persistence, and backend saved-profile ownership. It is not an exhaustive security audit or a review of every statistics route.

Claude's `frontend-design` skill guided the visual work. Existing artwork, fonts, game identities, routes, and backend contracts remain in place. No dependencies, production configuration, or backend data were changed.

## Changes

- **StatsConnect:** clearer illustrated game cards, accurate connection labels, a numbered onboarding strip instead of unsupported uptime claims, better connected-profile hierarchy, and corrected desktop hero spacing.
- **Brawl Stars:** tighter responsive hero, linked brawler cards, clearer ranking and event sections, and separate loading, failure, empty, and populated states.
- **Clash Royale:** a wrapping blue-and-gold hero, visible player/clan selection, tag instructions, one player-report introduction instead of repeated empty panels, and semantic deck statistics.
- **Shared navigation:** focus indicators across all apps, reduced-motion handling, explicit menu-control relationships, and cleanup when an open mobile menu crosses the desktop breakpoint.
- **Test coverage:** the hub's existing launch-profile tests now run through `pnpm test` instead of requiring a separate command.

## Confirmed defects fixed

## Open findings requiring decisions

### P2: Cookie truncation can hide saved profiles

`packages/auth/src/browser-connected-profiles.ts` prefers the compact cross-site cookie over complete localStorage. The cookie drops oldest entries to fit its size budget, truncates names to 24 characters, and omits timestamps. A reproduction saved 16 profiles and reloaded 15 while localStorage still held all 16.

Simply preferring or merging localStorage is unsafe because it can resurrect deletions from another subdomain. The synchronization contract needs revision metadata or an explicit overflow marker before precedence changes. No persistence changes were made in this pass.

### P2: Client and backend saved-profile limits disagree

`packages/auth/src/connected-profiles.ts` keeps eight profiles per game. `packages/backend/convex/hub/savedProfiles.ts` returns at most sixteen total, but its save and merge handlers do not enforce those limits. Hidden rows can retain connected refresh demand because client-side eviction does not unregister them.

Choose whether exceeding the limit rejects a save or explicitly replaces a profile. Test ninth-per-game and seventeenth-total saves at the handler boundary. Automatic eviction was not added because it changes saved user data.
